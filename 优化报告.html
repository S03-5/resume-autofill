03五个新功能，怎么用

每节先讲「解决什么」，再给可以直接照做的操作。

① 组件型表单能填了

校招站点（Moka / 北森 / 牛客 / 各厂自建系统）大多是组件库渲染的： 下拉框是个 <div>、日期框是 readonly 的、省市区是三列级联。 以前插件对这些完全无感，现在分三层处理：

  • 非原生下拉——模拟 mousedown 打开面板，按「完全相等 → 前缀 → 包含」三级匹配选项后点击
  • 日期选择器——先试直接赋值，失败则打开面板按「年 → 月 → 日」逐级点选
  • 省市区级联——把「吉林省长春市南关区」拆成三级逐列点击，支持自治区、自治州、直辖市、单列市
  • 重复经历块——先数页面有几行、你数据有几条，不够就自动点「＋ 添加」补出行数再填
  • 简历附件——弹窗里传一次，填写时自动塞进上传框

你不需要做任何事，打开表单页点填写就行。相关开关在弹窗「⚙️ 填写选项」里的「深度填充」和「自动上传简历附件」。

② 悬浮球 · 一键撤销 · 填写战报

在表单页右下角会出现一个可拖拽的小球，点一下展开菜单。填完之后不再是一脸茫然：

  • 战报浮层——顶部显示 已填 12 · 待手填 3，分两组列出「插件没填上的」（带具体原因，如「选项里没有『共青团员』」）和「页面里没认出来的空白框」
  • 点战报里的任意一条，页面会自动滚过去并高亮那个框——不用肉眼找
  • 一键撤销——填写前把每个控件的原值存成快照，撤销时逐个还原，并清掉绿色高亮
  • 战报 15 秒后自动收起；鼠标停在上面则保留

撤销的四个入口：悬浮球菜单 / 战报里的「↩ 撤销这次填写」/ 弹窗按钮 / 快捷键 Ctrl+Shift+Z。

页面刷新后快照失效，会提示需要重新填写——这是刻意的，比悄悄恢复到错误状态安全。

③ 让插件自己学会新网站（字段记忆 + 点选）

这是这次最有价值的一块。以前插件认不出来的框只能改代码，现在你自己教它：

方式 A：从战报里补

填完后战报里「页面里没认出来的空白框」每一行右侧有「记住」按钮 → 点它 → 弹出字段选择面板（带搜索框）→ 选中 → 插件立刻记住并当场按新映射填一次。

方式 B：主动点选（推荐首次遇到新站点时用）

  1. 悬浮球菜单 → 🎯 点选生成适配器页面顶部出现提示条，鼠标划过输入框会蓝色描边
  2. 点上要记录的框弹出字段选择面板，面板上会写明将使用的选择器
  3. 选完字段绿色描边表示已收集，并弹出「已收集 N 个字段映射」面板
  4. 面板上可「继续点选 / 复制代码 / 完成」「复制代码」生成的是一段能直接粘进 content/sites.js 的适配器片段

记下来的东西能扛住改版：同时存了「精确选择器」和「指纹」（tag + name / placeholder / 标签文字）。 选择器找不到时按指纹兜底；选择器在全页不唯一时宁可不认，也不会把值填到错的框上。

命中优先级：记忆 > 站点适配器 > 智能识别。你手动确认过的东西，永远排在机器猜测前面。

弹窗里有「字段记忆」管理区，可以按站点查看 / 单条删除 / 清空，也能直接导出适配器代码。想对比纯智能识别的效果，可在「⚙️ 填写选项」里临时关掉「优先使用字段记忆」。

④ 多套简历方案 + 期望职位自动推断

多套方案

弹窗顶部现在是方案条：下拉选方案，＋ 新建、⧉ 复制、✎ 重命名、🗑 删除。 一套方案 = 字段数据 + 经历块 + 简历附件，切换时三者一起换。

  • 切换是手动的——不会因为你今天看了个新岗位就偷偷把简历换掉
  • 附件按内容去重——复制方案时附件只存一份引用，不会因为方案变多把存储撑爆
  • 老数据无感升级——升级后第一次打开会把已有的简历原样包成一套「默认方案」，不丢内容

建议这样用：建「机械岗」「硬件岗」「通用」三套，投递前先在下拉里切一下。

期望职位自动推断

校招站点标题几乎都带岗位名（示例：字节跳动-后端开发工程师-校招）。 插件会把标题按分隔符切段打分——含岗位词加 10 分，含公司词扣 12 分，含站点词扣 20 分，取最高分那段：

  • 门槛：没有岗位词的段落一律不要，宁可留空也不乱填
  • 斜杠不轻易切：只有斜杠两侧带空格时才当分隔符，所以「C/C++开发工程师」不会被切成两段
  • 城市：标题里找城市名（含「北上广深」这类简称）+ 拼音域名兜底
  • 推断结果总是覆盖简历里的写死值，但会在战报浮层里单独显示一段「岗位已按当前页面调整为 XXX」，所以你随时知道填的和写的不一样
不想要这个行为？在「⚙️ 填写选项」里关掉「按当前岗位自动调整期望职位 / 期望城市」即可。

⑤ 投递台账

投递本身变成可追踪的数据。一条记录包含：公司、岗位、城市、链接、来源站点、状态、备注、时间。

状态含义
已投递刚投出去，等消息
笔试收到笔试邀请
面试中进入面试流程
已通过拿到 offer
已拒 / 无回应结束，归档

三种记账方式

  1. 投递成功后自动提示提交后插件隔 2.6 秒看一眼当前页是不是「投递成功」页，是的话右下角弹卡：「检测到投递成功 · XX公司-XX岗位 要不要记进投递台账？」，点「记一笔」完成。绝不自动记账——误记比漏记更难清理
  2. 悬浮球菜单 → 📝 记一笔投递不想等检测，或者投递发生在别的页面时用
  3. 弹窗 → 投递台账 → ✎ 手动加一条补录官网投的、内推的

弹窗里能做什么

  • 统计：今天投了几家 / 本周投了几家 / 还在等结果几家
  • 筛选 + 搜索：按状态筛，按公司 / 岗位 / 备注搜
  • 改状态、编辑备注、删除单条、清空
  • 📤 导出 CSV——开头写了 UTF-8 BOM，Excel 双击打开中文不乱码

同链接去重：比对前先归一化（链接去掉参数和末尾斜杠、公司名去全角空白、岗位名忽略大小写）， 同一个岗位重复记只会合并成一条，不会堆成两行。最多保留 500 条，超出丢最旧的。

识别成功页时特意排除了「我的投递记录」「投递列表」这类页面——它们本身就含「投递」二字， 不加排除规则会天天误弹。

04日常使用流程

从装好到投完一份，推荐按这个顺序走。

  1. 更新扩展打开 edge://extensions/（Chrome 用 chrome://extensions/），在「简历助手」卡片上点 🔄 重新加载。如果是新装，点「加载已解压的扩展程序」选本文件夹
  2. 确认版本是 2.0.0弹窗里显示的版本号是直接读 manifest 的，改一处不会不同步
  3. 建方案弹窗顶部方案条 → ＋ 新建「机械岗」，再 ⧉ 复制一份改成「硬件岗」。每套方案单独编辑字段、经历块、附件
  4. 首次遇到新站点，先教它悬浮球 → 🎯 点选生成适配器，把插件没认出来的框点一遍。同一个站点只需做一次
  5. 投递前切方案投机械岗就切「机械岗」方案
  6. 填写悬浮球点「⚡ 填写当前页面」，或按 Ctrl+Shift+F，或右键菜单「用简历数据填写本页表单」
  7. 看战报、补漏看右下角战报：绿色高亮是已填；点条目跳到对应框；没认出来的框点「记住」教会它
  8. 填错了就撤销Ctrl+Shift+Z，或战报里的「↩ 撤销这次填写」
  9. 提交后记账成功页会弹卡 → 点「记一笔」
  10. 定期看台账弹窗「投递台账」看今天/本周投了几家、几家在等结果，把该改状态的改掉，需要时导出 CSV

05顺带修掉的 6 个真实缺陷

都是自动化实测暴露出来的——不修的话，前面的功能等于白做。

步骤缺陷原因与修法
二 非原生下拉全部填不上 防误填关键词里有 search，而 antd Select 的内部输入框 class 恰好是 ant-select-selection-search-input。修法：class 不再参与组件型控件的判定
二 下拉面板会串台 [class*='panel'] 把站点自己的布局卡片也当成下拉面板；且按「取最后一个可见面板」猜测归属，多控件同页时会拿错。修法：对比点击前后「新出现的面板」来判定归属
二 省市区级联永远填不到第二级 选项 class 是 ant-cascader-menu-item，同样含 cascader-menu，于是「第 2 列」取到的是某个选项。修法：按 class 里的 item 排除选项
三 自定义字段在悬浮球 / 快捷键通路上永远填不上 第二步换了填写入口后只把 resumeData 传给了引擎，没把自定义字段（键是 custom_<id>）合进数据。修法：两条通路共用 buildFillData()
三 hud.js 里 3 个变量漏声明，面板打不开 变成了隐式全局变量，页面有同名全局时静默串台。修法：显式声明 + ensure() 在节点缺失时自愈重建
三 字段分组定义了两份 弹窗一份、页面里一份，迟早不一致。修法：统一到 content/sites.js 的 JIANLI_FIELD_GROUPS
为了不再犯同类错误，静态检查加了这几条：
  • 所有 checkbox 开关必须接上事件——第三步就漏接过一次，表现为「界面有开关但拨了没用」
  • background.js 的注入清单必须和 manifest.json 完全一致——不一致会导致部分页面缺模块
  • content_scripts 顺序必须是 sites → widgets → blocks → memory → infer → ledger → hud → content
  • 弹窗里引用的每个 id 必须真实存在；新模块必须在弹窗和内容脚本两边都已加载

07已知限制与建议

已知限制

  • 扩展行为需要你手动实测。系统 Chrome 152 起封禁了 --load-extension， 没法自动化加载扩展去实测真实站点。测试页是普通网页（mock 了 chrome API）， 所以自动化测的是逻辑，真实站点的表现仍需你投几次验证。
  • 推断有边界。标题里完全没有岗位信息（比如标题只写「职位详情」）时，插件会留空而不是猜—— 这是设计选择，不是 bug。
  • 成功页检测是启发式的。遇到没见过的成功页文案可能识别不到，用悬浮球的「📝 记一笔投递」兜底即可。
  • 台账上限 500 条，超出丢最旧的；建议定期导出 CSV 留档。

建议的下一步

  • 真实站点实测三轮：随便挑 3 家投一下，重点看组件型下拉、经历块增行、成功页检测这三处。 发现问题告诉我具体站点和现象即可。
  • 把常用站点固化下来：用点选方式教会 3～5 个你高频投的站点后， 把生成的适配器代码贴进 content/sites.js，这样换电脑 / 重装也能直接用。
